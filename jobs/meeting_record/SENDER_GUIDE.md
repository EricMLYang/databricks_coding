# 會議紀錄信件：寄信者注意事項（給轉寄 / 撰寫會議紀錄的同仁）

你轉寄到會議紀錄信箱的信，會由程式自動讀取、切段、去識別，再由 AI 把內容拆成一條條「誰在什麼時候說了什麼」，最後整理成月報與可查詢的紀錄。程式只看**信件正文的文字**。下面是依目前流程整理的注意事項；照做可以讓你的會議內容被完整收進來，不照做的部分不會報錯，只是**那些內容會靜悄悄地不見**。

更新日期：2026-10-19（依 W1 清洗流程 cleaner 0.2、萃取 prompt 0.2）

---

## 一、一定要做

| 事項 | 原因 |
|---|---|
| **會議內容寫在信件正文**，不要只放附件 | 附件（Excel / PPT / PDF / Word）**完全不讀**。只有「請見附件」的信會被歸成「附件型」直接跳過。關鍵數字、結論請貼成文字 |
| **不要用截圖 / 圖片放內容** | 圖片一律變成 `[image]` 佔位，表格截圖、白板照片、投影片截圖裡的字都不見 |
| **一封信一場會議**（或同一系列同一天的紀要） | 程式以「轉寄標頭」與「行首型號」切段；兩場會議混在一封信裡，日期與客戶會對錯 |
| **主旨寫清楚**：客戶 ＋ 應用 / 機種 ＋ 會議名稱 ＋ 日期，例 `acer MNT Monthly Meeting 2026-09-03` | 主旨是程式判斷「哪個客戶」的第一依據（權重最高），也是月報裡「場合」的名稱。同一系列會議的主旨請**每次維持同樣寫法**，才能被當成同一場合累積 |
| **保留原話，不要先改寫成結論** | 詞彙與口徑藏在原話裡（「risk buy 兩週」改成「提前備料兩週」就萃不出來）。AI 會逐字引用原句當證據，被改寫過的句子引用不到 |

## 二、建議這樣寫，萃取會更準

| 事項 | 效果 |
|---|---|
| **每條紀要寫明客戶**（VD、acer、Dell…），不要只在信首提一次 | 目前約一半的條目程式判不出客戶是誰（因為原文沒寫），這些條目在「按客戶」的月報裡會漏掉 |
| **型號寫完整並放在行首**，例 `M270QAN06.A：…`、`T430QVN04.5：…` | 行首型號是紀要的切段依據；型號前綴（B / M / T）也用來判 NB / MNT / TV |
| 紀要用 **`ITEM` ＋ 日期**（例 `ITEM 9月3日`）分節 | 程式從這行取各段的會議日期；沒有就只能用寄信日期代替（會標成「推測」） |
| thread 回覆保留 Outlook 的 **From: / Sent: / Subject:** 標頭 | 這是判斷「誰在哪天說的」的依據；手動刪掉標頭，整段的發言人與日期就取不到 |
| **誰說的要寫**（「TCL 要求…」「我方回覆…」） | 沒有主詞的句子，發言方只能用猜的，信心會被壓低 |
| **數字帶單位與期間**（`Q4 20K`、`10/14–10/26 入料`） | 數字沒有單位 / 期間，AI 會收進來但無法對照 Sales Brief |
| **一段一個主題**，不要一句話塞三件事 | AI 會把一句話拆成多條，太擠的句子拆錯率高 |
| 整封信**少於 150 字的內容不收** | 太短的段落當成雜訊略過（簽名檔、寒暄）。真正的會議內容請寫夠 |
| 單一段落**超過 12,000 字**請拆成多封或多個 ITEM | 超長段仍會送 AI，但輸出會被截斷、部分條目遺失 |

## 三、不用擔心的事（程式會自動處理）

- **人名、email、工號**：全部換成代號（`<P01>`），不會出現在任何輸出。可以照常 cc、照常寫人名。
- **公司免責聲明、ESG 宣導、外部信警語**：自動刪除。
- **轉寄標頭的 To / Cc / Bcc**：自動刪除，只留 From / Sent / Subject。
- **同一段紀要連續幾週重複貼**：自動合併成一條（保留最早那次），不用手動刪舊內容。
- **網址、cid 圖片、Outlook 版面殘渣**：自動清掉。
- **中英夾雜、簡體字**：照原文收（簡體目前不轉繁體，但不影響萃取）。

## 四、目前做不到的（已知限制）

| 限制 | 說明 | 狀態 |
|---|---|---|
| 附件不讀 | Excel / PPT / PDF / Word 內容不會進系統 | 規劃中，無時程 |
| 圖片不讀 | 表格截圖、照片、投影片圖一律略過 | 無計畫 |
| **從 Word 貼進 Outlook 的信可能整封讀不到** | 約 29% 的歷史信件，正文在進資料平台前就被截斷（只剩 Word 樣式碼）。原因在資料擷取端，處理中。在修好前：**用純文字或 Outlook 直接打字**，不要從 Word 整頁貼上 | 追 ETL 中 |
| 一封信多場會議 | 日期、客戶可能對錯 | 請分封寄 |
| 表格 | 文字表格會被攤平成 `欄1 \| 欄2 \| 欄3` 一行，欄位對應靠 AI 讀；複雜表格建議改成條列 | 可用，不保證 |
| 日期判讀 | 沒有 `ITEM m月d日` 或 `Sent:` 的段落，日期用寄信日期代替 | 已標示 |
| 簡轉繁 | 不轉 | Phase 1 不做 |

## 五、一個合格的紀要信長這樣

```
主旨：acer MNT Monthly Meeting 2026-09-03

ITEM 9月3日
M270QAN06.A：acer 確認 Q4 需求由 30K 上修到 35K，要求 10/14 前回覆 allocation。
M270QAN06.A：我方回覆目前 allocation 30K，多出的 5K 需 10/10 前確認產能。
T430QVN04.5：量產出貨 VLRR 不良目前 603 ppm，acer 要求 400 dppm 以下。

ITEM 9月10日
M270QAN06.A：acer 提到 BOE 27 吋 QHD 200Hz OC 報價約 $42–43。
```

每行一個型號、一個主張、有客戶、有數字單位、有日期分節。附件可以附，但重點已在正文。
