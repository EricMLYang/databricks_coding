## 0. 核心問題：爬蟲分類是「一家一類」，報告需要「一家多視角」

爬蟲主檔（MI_Crawler `data/companies.json`，193 家）每家只有一個 `category`，決定 Volume 子目錄、前端 Tab、重要性規則：

| category | 家數 | 爬蟲端定義 |
| --- | --- | --- |
| SUPPLIER | 161 | 供應商 YAML 全部，**含原本就在 YAML 的半導體公司**（台積電 2330、聯電 2303、世界先進 5347、力積電 6770、華邦 2344、旺宏 2337、京元電 2449、頎邦 6147、聯發科 2454、瑞昱 2379、驅動 IC 廠、康寧 GLW、東京威力 8035、SCREEN 7735、Ulvac 6728…） |
| SEMI | 14 | 2026-10-15 新增、**只收 YAML 沒有的新公司**：NVDA / AMD / AVGO / INTC / MU / MRVL / COHR / AMKR / 日月光 3711 / 力成 6239 / 欣興 3037 / 南亞科 2408 / SK hynix / 中際旭創。爬蟲規則 `CATEGORY_RANK`：SUPPLIER 勝過 SEMI |
| PANEL_PEER | 9 | 三星、LGD、天馬、TCL 科技、京東方、維信諾、**友達 2409**、群創 3481、夏普 |
| CUSTOMER | 9 | TCL 電子、冠捷、聯想、Dell、HP、海信視像、宏碁、華碩、微星 |

所以若報告直接拿 `category` 當分流：
- 半導體視角會**漏掉**台積電、聯電、京元電、頎邦、康寧（玻璃基板 / 光通訊）等對友達封裝 / 光通訊題目最重要的公司；
- 三星同時是一線面板對手與最大品牌客戶，只會出現在一邊；
- 群創也做 FOPLP，既是面板同業也是封裝對標。

**解法：報告端自己維護「視角（report view）」對應，與爬蟲分類脫鉤。** 爬蟲分類只管檔案落哪個目錄；報告端每家公司可掛多個視角，一個視角一份報告。

```
視角 view        預設來源分類      另外加掛（override，報告端清單）
supplier         SUPPLIER         —
peer             PANEL_PEER       —（友達 2409 自己不產報告，只當對照基準）
semi             SEMI             SUPPLIER 裡的半導體 / 封裝 / 光通訊相關：2330 2303 5347 6770 2449 6147 2344 2337 GLW（玻璃基板 / 光通訊）… + 群創 3481（FOPLP）
customer（之後）  CUSTOMER         三星 005930
```

- 對應表放哪：Databricks 只能貼 cell（不能上傳檔案），所以 **override 清單內嵌在 notebook 一個 cell**（`VIEW_OVERRIDES = {"TPE:2330": ["semi"], …}`），預設規則 `category → view` 也在同一 cell；要查歷史就看 gold 的 `report_kind`。不另建設定表。
- 一家兩視角 = 兩份報告、兩次 LLM 呼叫（讀者不同：採購 vs 策略 / 新事業）。重疊公司約 10 家，每季多 10 次呼叫，可接受。不建議合併成一份雙節報告，分發對象不同。

## 1. 程式面：一支 notebook、三個設定檔（profile），不拆支

拆支的代價是七成 cell 重複（[c03] 數字、[c04] 工作清單、[c06] 圖、[c08]–[c11] 讀寫流程），Databricks 又只能複製貼上。改成 profile：

| 會因視角不同的 | 現在 | 改法 |
| --- | --- | --- |
| 系統角色、結論四面向、規則用語 | [c05] `SYSTEM_PROMPT`、`ACTION_AREAS` | `PROFILES[view]["system_prompt"]` / `["dimensions"]`；`prompt_version` 每個 profile 自帶（`supplier 2.1` / `peer 1.0` / `semi 1.0`） |
| 章節標題、專屬節（採購觀察 → 競爭觀察 / 新事業觀察）、對照表 | [c07] `SECTION_TITLES`、render 函式 | profile 帶標題表與「要不要對照基準公司」開關 |
| 關注指標與排序 | [c02] `INDICATORS` 11 項 | 共用 11 項，profile 另給「重點 4–5 項」放 KPI 卡（同業看毛利 / 營益率 / 存貨天數 / 資本支出比；SEMI 看營收成長 / 資本支出 / 毛利） |
| 落地 | gold `g_ir_calendar_ir_report` 鍵 (company_key, period)；Volume `reports/<分類>/<公司>/` | gold **鍵加 `report_kind`**（表目前 0 列，趁未上線改 [c19b] DDL 直接重建）；Volume 改 `reports/<view>/<公司>/`；檔名加 `_<view>_` |
| 工作清單 | [c04] 以 (公司, 期別) | 以 (公司, 期別, view) 為單位；`categories` widget 改成 `views`（`supplier,peer,semi`），範圍過濾改用 view 對應而不是 `s_document_text.category` |

共用不動：當季為準 / 只有彙整也產 / 來源雜湊 / 重做規則、[c03] 換算、[c06] 圖表、[c08] LLM 呼叫、bronze 記錄、`max_reports` 費用閘門。

何時才拆支：某視角的資料來源或章節結構差到一半以上（例如客戶視角要接 Sales Brief 出貨資料、同業要做多家並排總表）。

## 2. 視角 peer：面板同業（以友達為主體的競爭情報）

**角色**：友達策略 / 競爭情報分析師，讀者是經營層與產品 / 業務主管。**問題意識**：對手這一季在規模、獲利、產能、技術、客戶上相對友達是拉開還是縮小，下一季會做什麼。

| 節 | 內容 | 資料來源 |
| --- | --- | --- |
| 給友達經營層的結論 | 4–6 句：對手趨勢 + 相對友達的位置 + 下一季要盯什麼 | LLM |
| 01 同期對照表（新增） | 對手 vs **友達同期**：營收 YoY、毛利率、營益率、稅後淨利率、存貨天數、資本支出 / 營收、負債比、營業現金流。幣別不同 → **只比比率與成長率，不比絕對金額**；絕對金額各自以本幣顯示 | `s_financials` 兩家（友達 TPE:2409 在 PANEL_PEER 內，有資料） |
| 02 財報實績與五年 / 五季圖 | 同供應商版 | `s_financials` |
| 03 產能與稼動 | 稼動率、新產線（8.6 代 OLED、IT OLED）、關線 / 轉型（LCD 退出）、資本支出計畫 | 文件 + 彙整 `management_views` |
| 04 產品組合與技術路線 | IT / TV / 車用 / 手機占比變化；OLED / Mini LED / Micro LED / 高階 IT；**與友達重疊的產品線標示** | 彙整 `business_segments` + 文件 |
| 05 價格與需求看法 | 面板報價評論、庫存水位、下季指引 | 彙整 `guidance` + 文件 |
| 06 客戶與策略動作 | 點名的品牌客戶、合資 / 併購、補貼、地緣政策 | 文件 |
| 07 Q&A 重點 | 同供應商版 | 彙整 `qa_highlights` |
| 08 競爭觀察（取代採購觀察） | 四面向：**威脅**（對手領先且正在擴大的地方）/ **機會**（對手退出或失誤）/ **技術與產能須跟進項**/ **客戶與價格面的應對** | LLM，規則同供應商版「不得推論未提及的事」 |

視角特有事項：
- **友達自己**：不產同業報告，但 `s_financials` 當對照；若要「外界怎麼讀友達法說」可選做 `self` 視角（待決 §6-3）。
- **三星**：母公司財報含半導體 / 手機，面板只在 Display 分部 → 對照表要用 `business_segments` 的 Display 列，整體數字只做參考並註明。
- **夏普**：會計年度 3 月底，季別要標明；**深滬四家**：爬蟲只抓財報不抓簡報（`wanted_by_market`），法說節多半靠彙整 / 新聞，報告要如實標「無簡報」。
- 爬蟲彙整 `management_views` 六主題詞彙是供應商導向定的，同業 / SEMI 是否夠用要看實際批次；不夠就請爬蟲端依 category 換詞彙（爬蟲端改動，報告端 [c02] `CONF_TOPICS` 跟著分 profile）。

## 3. 視角 semi：半導體（友達跨入先進封裝 / 光通訊的外部環境）

**角色**：友達新事業 / 策略分析師，讀者是新事業與技術主管。**問題意識**：三個題目（爬蟲端 10-15 分組）——**A 封裝 / 載板**（FOPLP、玻璃基板、ABF）、**B 光通訊 / 矽光子**（CPO、光模組、雷射）、**C 景氣風向**（AI 資本支出、HBM / DRAM 報價、成熟製程）——這一季的需求、產能、技術時程、價格與生態系有什麼變化，對友達切入的窗口與門檻有何影響。

| 節 | 內容 | 資料來源 |
| --- | --- | --- |
| 給友達新事業主管的結論 | 4–6 句：該公司在 A/B/C 哪個題目、本季訊號、對友達的時間窗 | LLM |
| 01 財務概況 | 同供應商版的 KPI / 實績 / 圖；**美股非曆年會計年度要標會計季**（NVDA / MRVL 1 月底、AVGO 10 月底、MU 8 月底、COHR 6 月底） | `s_financials` |
| 02 需求與資本支出訊號 | AI 加速器 / 資料中心需求、CoWoS / 先進封裝產能、HBM 出貨、光模組 / CPO 量產時程、capex 指引 | 彙整 + 文件 |
| 03 技術路線與時程 | 面板級封裝、玻璃核心載板、2.5D/3D、CPO / 矽光子、1.6T、下一代記憶體；**點名的量產年份** | 文件（簡報為主） |
| 04 產能、供需與價格 | 先進封裝 / ABF 載板 / DRAM 的緊俏與報價方向、長約 | 彙整 `key_numbers` + 文件 |
| 05 生態系：夥伴與競爭者 | 點名的合作對象與客戶（台積電 / 英特爾 / 日月光玻璃基板、OSAT 進 FOPLP）；**標示哪些是友達 FOPLP / CPO 的直接對標** | 文件 |
| 06 Q&A 重點 | 同供應商版 | 彙整 |
| 07 新事業觀察（取代採購觀察） | 四面向：**市場窗口**（需求何時放量）/ **技術門檻與對標**（對手規格與時程 vs 友達）/ **潛在客戶或夥伴** / **競爭威脅**（誰在搶同一塊） | LLM |

## 4. 視角 customer（之後，先記）

品牌客戶看的是**需求端**：出貨 / 庫存 / 指引、產品組合（NB / MNT / TV 高階化）、對面板採購的評論、區域市場。結論面向：需求訊號 / 產品機會 / 庫存與價格壓力 / 份額風險。資料上最可能要接 Sales Brief（`app_sales_*`）的實際出貨，那時再評估是否拆支。三星同時掛 peer + customer。
